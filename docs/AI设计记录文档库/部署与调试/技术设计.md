## 独立运行

- 设备端与服务端各有启动入口和配置，首版可在同一 Windows 10 电脑运行。
- 设备端连接可配置的服务端地址，服务端选择 S2S 或串联模式并配置相应提供方。
- 路径相对项目根目录或显式配置的数据目录解析，部署脚本调用各端独立入口。
- 本地模型的依赖和资源按适配器管理，在线提供方连接在服务端建立。
- 模型密钥通过本机私有配置加载，文档及常规日志只记录提供方名称和状态。

## 联调方案

| 层次 | 验证内容 |
| --- | --- |
| 音频 | Windows 麦克风、输出设备及唤醒连续音频 |
| 协议 | 模拟设备发送音频、结束和取消，验证回复关联 |
| 模型 | 优先千问 S2S，另验豆包 STT、DeepSeek LLM、Windows TTS 串联路径 |
| 闭环 | 连说唤醒词与内容，听到对应回复 |
| 业务 | 测试 Findtools 接口和模拟灯光执行 |

- 对断网、模型超时和设备重启分别验证错误与恢复。
- CPU、内存、音频积压及回复延迟需实测，指标待确定。
- 树莓派和 ESP32 后续单独适配和验收。

## 当前入口与验证

- Python 3.12 独立虚拟环境，依赖快照见根目录 `requirements-lock.txt`。
- `setup.cmd` 准备环境、配置和模型，`start-server.cmd` 与 `start-device.cmd` 分别启动两端。
- 默认监听 localhost 8765，平台 token 自动生成在被忽略的本地配置中。
- 项目位于桌面 `openspeech/`，Git 元数据保存在本目录 `.git/`，当前未配置远程。Findtools 不再记录语音子模块指针。
- 本机启用模型回归后 24 项检查通过，覆盖串联协议、S2S 会话、音频连续性及真实本地 WebSocket 传输；Windows TTS 和 Vosk 合成样本唤醒通过。
- 独立服务进程的 HTTP 健康检查、鉴权能力接口及缺失凭据错误路径通过。
- 真实人声、真实云端调用、树莓派、ESP32 以及 Findtools 业务联调待验证。
- 具体命令见[运行指南](../../运行指南.md)。
- S2S 仅检查百炼 API Key 和业务空间地址，串联模式检查豆包和 DeepSeek。健康状态只表示配置是否齐全，不表示账号授权和模型效果已验证。
- 本地回环集成测试实际运行设备客户端、平台服务及模拟千问 WebSocket，检查分片顺序、回复流与断线后关闭上游；不访问云端。
- CHG-002，2026-11-04，增加默认 S2S 配置、按模式健康检查及本地回环流式测试，保留串联启动方式。
