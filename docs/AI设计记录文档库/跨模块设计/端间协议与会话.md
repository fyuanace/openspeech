- 设计类型为跨模块设计，涉及设备端、服务端、通用接入。
- 对应开发者设计为[设备端](../../开发者设计文档库/设备端.md)、[服务端](../../开发者设计文档库/服务端.md)、[通用接入](../../开发者设计文档库/通用接入.md)。

- 更新日期为 2026-11-04，以下为拟议方案，当前待开发。

## 接口边界

| 通道 | 方向 | 内容 |
| --- | --- | --- |
| 会话控制 | 双向 | 建立、能力协商、音频结束、取消、状态及错误 |
| 输入音频 | 设备端到服务端 | 带顺序与格式信息的音频分片 |
| 回复 | 服务端到设备端 | 转写、回复文本、回复音频及完成状态 |

- 传输协议待选，可评估长连接承载控制与双向音频。
- 设备、会话、轮次标识贯穿 STT、LLM、TTS 与业务调用。
- 能力协商包含编码、采样率、声道、采样类型和输入输出能力。
- 端间接口独立于豆包、DeepSeek 或其他模型的私有协议。

## 顺序与失败处理

1. 设备端持续缓冲，唤醒触发后建立本轮会话。
2. 按音频顺序发送保留片段并接续实时流，服务端保持原始时间顺序。
3. 收到音频结束后完成转写，进入对话及语音合成。
4. 设备只播放当前有效轮次的音频，最终播放状态回传。

- 本地结束检测或服务端结束检测可通过能力协商确定，设备必须提供明确结束信号或约定机制。
- 网络慢于采音时使用有界缓冲和明确失败，避免静默丢弃指令开头。
- 断线重连时明确取消、恢复或重新提交策略，避免自动重复执行业务。
- 接口版本、连接认证、背压阈值、重试与超时取值待正式定义。

## 验证计划

- 延迟唤醒检测与建连，验证音频连续且顺序正确。
- 模拟乱序、重复、断线与迟到回复，验证会话隔离及去重。
- Windows 首版通过真实音频验证，后续终端使用相同接口用例。
