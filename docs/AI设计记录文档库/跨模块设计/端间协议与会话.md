# 端间协议与会话

- 设计类型为跨模块设计，涉及设备端、服务端、通用接入。
- 对应开发者设计为[设备端](../../开发者设计文档库/设备端.md)、[服务端](../../开发者设计文档库/服务端.md)、[通用接入](../../开发者设计文档库/通用接入.md)。
- 返回[技术索引](../index.md)。
- 更新日期为 2026-11-05。语音采用串联 HTTP v1 或 S2S WebSocket v1，Windows 工具采用独立的 MCP Streamable HTTP 端点。

## 当前接口

| 方法与路径 | 输入 | 输出 |
| --- | --- | --- |
| GET /health | 无需鉴权 | 已配置或缺少云端配置，不返回密钥 |
| GET /v1/capabilities | Bearer token | 版本、音频规格及当前适配器 |
| POST /v1/turns | Bearer token、设备/会话/轮次 ID、WAV 请求体 | 识别文字、回复、Base64 WAV 或错误 |
| WS /v1/realtime | Bearer token、会话控制事件、二进制 PCM | 实时音频与文字增量、完成或错误事件 |

- 能力接口声明 mode、modes、endpoint、streaming、barge_in 和音频格式。新会话使用当前服务端模式，错误模式端点明确拒绝。设备启动或继续监听时自动选择。
- 以下为串联模式 POST /v1/turns 契约。输入为 16 kHz、单声道、16-bit PCM WAV，最多 35 秒。
- 请求头为 `X-Device-Id`、`X-Session-Id`、`X-Turn-Id`，标识长度 1–100，字符限字母、数字、下划线、点和短横线。
- 可选 `X-Wake-Word` 使用 UTF-8 十六进制编码，服务端仅移除识别文本开头的唤醒词。
- 回复包含 `version`、`device_id`、`session_id`、`turn_id`、`text`、`reply`、`audio_format` 和 `audio`。
- TTS 失败时 `audio` 为空并带 `audio_error`，识别和回复文本保留。
- 其他失败返回 `error` 和 `stage`。输入错误使用 400/413/415，鉴权失败使用 401，忙或轮次冲突使用 409，模型失败使用 502。
- HTTP 请求传完整指令，完整响应返回后才播放，当前 `streaming=false`。

## S2S 实时接口

| 方向 | 事件 | 说明 |
| --- | --- | --- |
| 设备 → 平台 | session.start | device_id、session_id。平台连接上游并完成配置后才确认就绪 |
| 平台 → 设备 | session.ready | 会话标识、输入 16 kHz、输出 24 kHz、单声道 PCM16、barge_in=false |
| 设备 → 平台 | turn.start | 新 turn_id，同一连接不得重用 |
| 设备 → 平台 | 二进制音频 | 无 WAV 头的 s16le PCM；单片不超过 6400 字节，整轮不超过 35 秒 |
| 设备 → 平台 | input.commit | turn_id；结束本轮输入，至少已有 100ms 音频；可附 device_timing |
| 平台 → 设备 | audio.delta / text.delta | Base64 PCM 或回复文字增量，均带 session_id、turn_id |
| 平台 → 设备 | turn.done | 模型 completed 且确实返回语音；完成后才能开始下一轮 |
| 设备 → 平台 | turn.metrics | 本轮播放结束后，可选提交 turn_id 与 device_timing；同一轮最多一次 |
| 平台 → 设备 | error | stage、简短可执行错误；本连接关闭，不自动重试 |
| 设备 → 平台 | session.close / 断开连接 | 停止处理并关闭上游；当前没有保留上下文的单轮取消接口 |
| 平台 → 设备 | session.ended | 模型请求结束当前会话，附会话和轮次标识。平台关闭连接，设备恢复等待唤醒 |

- S2S streaming=true，首轮本地唤醒。追问在同一连接中以新的轮次 ID 提交，建连期间缓冲当前轮音频。
- 每个设备会话最多一个连接，全局最多两个连接；连接内顺序处理轮次。
- 首事件等待 10 秒；就绪后空闲 180 秒；单轮输入 45 秒墙钟上限；上游生成最多 120 秒。
- 会话最长 30 分钟、最多 128 轮；到期提示重新连接，不静默新建会话。
- 单轮输出最多两分钟 PCM，文字最多 16000 字符。网络与音频队列有界，避免慢消费者无限积压。
- 设备断开时取消生成转发并关闭上游，及时释放连接。模型错误不会自动切换到串联模式。
- 麦克风采集丢帧或应用采音队列溢出时，S2S 设备端丢弃受影响的录音，重开采音并回到等待唤醒。恢复后两秒内再次溢出时，暂停监听并提示检查麦克风。
- 同一上游连接维护音频上下文，不把 S2S 会话转换为串联文字历史。
- 接口实现见 [realtime_server.py](../../../voice_platform/realtime_server.py)，提供方事件映射见[服务端技术设计](../服务端/技术设计.md)。

## 设备计时回报

- 此扩展属于 S2S v1 的可选字段与事件。旧客户端可不提供；新客户端需配套支持回报的服务端。
- 设备单调时钟与服务端单调时钟各自测量，不相减，不依赖两机时钟同步。
- 初次提交、播放回报各有独立白名单；播放回报不能修改采音或服务端计时。

| 事件 | 字段 | 含义 |
| --- | --- | --- |
| input.commit | entry | wake、follow_up 或 file |
| input.commit | speech_ms | 估算开口至最后有声帧；含唤醒词、句中停顿 |
| input.commit | wake_ms | 估算开口至本地检测到唤醒，仅 wake 提供 |
| input.commit | endpoint_ms | 最后有声帧至设备完成采音；含静音判停和本地处理 |
| input.commit | submit_ms | 采音完成至提交；含尚未完成的建连与余量发送 |
| input.commit | input_elapsed_ms | 估算开口至提交 |
| turn.metrics | reply_wait_ms | 提交至首段音频写入声卡前 |
| turn.metrics | playback_ms | 首段写入至输出流排空；含后续生成和传输 |
| turn.metrics | total_ms | 估算开口至输出流排空 |

- 主流程五段顺序相接。`wake_ms` 与主流程重叠，不能重复相加。
- “说完到开播” = endpoint_ms + submit_ms + reply_wait_ms。
- “完整交互” = input_elapsed_ms + reply_wait_ms + playback_ms。不包含开口前待机时间。
- 上传音频长度含前置缓冲和静音；接收窗口与说话重叠，二者不计入主流程相加。
- 无回报、结束会话或处理中断时显示缺失；不能推定零耗时或已播放。

## 设备工具

- Windows MCP 服务监听 `127.0.0.1:18766`，由小美通过同一套 [MCP 客户端](../通用接入/技术设计.md#外部-mcp-工具)连接。
- `set_volume` 由设备服务声明和实现。参数为 0–100 的整数 `percent`，成功时返回 Windows 实际音量。

## 一语即达与时序

1. 设备持续保留唤醒前音频，检测到唤醒后接续后续采样。
2. S2S 立即提交缓冲前缀并传送后续帧，静音结束时提交；串联模式收齐一段 WAV 后提交。
3. S2S 将音频直接交给实时模型并转发回复流；串联模式依次完成 STT、LLM、TTS。
4. 设备核对会话与轮次并播放音频，S2S 边收边播，完成后恢复监听。

连续采集发生在本地，因此建连与云端识别不要求用户在唤醒后等待。处理与播放阶段暂停采音。播报完成后开放免唤醒追问，超时关闭连接并结束当前对话。

## 音频处理边界

目标为带地方口音的普通话与四川话。以下区分当前实现和后续方案，不表示降噪或方言适配已完成。

| 环节 | 当前实现 | 后续方案 |
| --- | --- | --- |
| 设备采音 | 请求 16 kHz、单声道、16-bit PCM；检测采音溢出 | 对其他硬件按实际采样率转换；不能只改采样率标签 |
| 设备增强 | 应用层未加降噪、自动增益或回声消除；系统及驱动增强未纳入配置管理 | 预留可关闭的增强处理，按同一批录音的对比结果启用 |
| 结束判断 | RMS 能量阈值与静音超时 | 评估语音活动检测 VAD，改善噪声下的结束判断；保留句首句尾余量 |
| 连续语音 | 同一 PCM 时间线交给唤醒与缓冲；串联形成 WAV，S2S 传连续 PCM | 增强引入延迟时保持时间对齐；不因 VAD 判断为静音而删除内部音频帧 |
| 平台服务端 | 串联校验 WAV；S2S 校验声明规格、分片字节数、轮次与长度 | 新格式明确扩展协议；模型适配器负责必要的格式转换 |
| 千问适配器 | PCM 分片以 Base64 放入 append 事件，回复为 24 kHz PCM | 增强仍由设备端优先处理，避免重复降噪 |
| 豆包适配器 | 串联模式使用完整 WAV 的 Base64；未重复降噪或裁剪 | 按提供方要求适配，避免多次有损编码和重复增强 |
| DeepSeek 适配器 | 仅在串联模式接收文字和上下文 | S2S 模式不调用它 |

- 先保留当前信号作为对比基线。检查原始采音的噪声、增益和削波，再决定是否启用轻量降噪或增益控制。
- 过度增强可能损伤语音细节，必须同时检查漏唤醒、误唤醒、识别效果及处理延迟。
- 回声消除优先放在设备端，需要同步的扬声器播放参考信号；当前播放期间暂停采音，完整 AEC 与打断仍未实现。
- 唤醒词和内容可直接连说。两种模式都保留前缀音频，不按固定时长裁剪。串联在识别后移除文本开头匹配的唤醒词；S2S 通过指令告知模型忽略唤醒词，无单独 ASR 步骤。
- 当前 v1 没有增强策略或语言偏好字段。未来需要两端协调增强时再增加版本化能力描述，不能假定这些字段已经存在。
- 口音与方言适配依赖唤醒、STT 模型及训练覆盖，音频增强不承担将四川话转换为普通话的职责。

依据：[Vosk 准确率排查](https://alphacephei.com/vosk/accuracy)、[WebRTC 音频处理接口](https://webrtc.googlesource.com/src/+/refs/heads/main/api/audio/audio_processing.h)、[豆包极速版接口](https://docs.volcengine.com/docs/doubao-voice/large-model-recording-file-lite-recognition-api?lang=en)。

## 串联模式状态与资源约束

- 每个设备和会话同一时间只处理一轮，全局最多两轮同时处理，超过限制返回忙状态。
- 同一轮 ID 和相同音频在缓存中重放时返回原结果。相同 ID 对应不同音频或唤醒词时拒绝。
- 结果缓存最多 32 条、有效期 5 分钟，仅在进程内保存。重启后清空，设备端不自动重试失败请求。
- 会话历史最多 64 个，每个保留最近 6 轮对话，按设备和会话隔离。
- 设备 HTTP 超时为 300 秒，单提供方请求或 TTS 超时为 90 秒。
- 远程取消、持久事件、流式分片与播放状态回传属于后续接口扩展。
