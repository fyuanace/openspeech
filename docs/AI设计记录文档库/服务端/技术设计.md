## 模型能力契约

以下为长期能力契约。首版具体签名为 transcribe(wav)、reply(messages)、synthesize(text)，流式及工具能力为后续扩展。

| 适配器 | 输入 | 标准输出 | 可选能力 |
| --- | --- | --- | --- |
| STTProvider | 带格式的音频流或完整音频、语言及会话信息 | 转写文字、最终结果标记、错误 | 中间结果、时间戳 |
| LLMProvider | 标准化消息列表、生成选项、可选业务工具描述 | 回复文本、完成状态、可选结构化业务请求、错误 | 流式输出、工具调用 |
| TTSProvider | 回复文本、音色及输出格式偏好 | 音频块或完整音频、实际格式、完成状态、错误 | 流式合成 |

- 提供方声明输入格式、流式支持、取消及其他可选能力。
- 在线适配器封装鉴权和远端协议，本地适配器封装模型加载或本地推理服务。
- 调用方依赖统一契约，供应商专有参数集中在提供方配置中。
- 不支持的能力明确返回，必要时将完整结果包装为单个最终输出。
- 模型切换按会话固定配置快照，避免同一轮处理中途切换。
- 供应商密钥保存在服务端配置，普通音频终端只需平台连接信息。

## 对话与合成

- 会话上下文按设备与会话隔离，语音结束后将最终转写提交对话处理。
- 识别前缀中的唤醒词移除策略需结合设备边界信息，避免简单全局文本替换。
- 当前只处理对话文本。工具调用和 Findtools 业务适配待实现，提示词要求不声称已执行实际业务。
- 首版可先收齐回复再合成，可选流式能力由适配器声明。
- 取消、超时与迟到结果按统一会话标识处理，避免播放上一轮回复。

## 首版实现

- STT 提供 `doubao` 和 `vosk` 两个适配器，后者可在本地识别完整指令。
- LLM 使用可配置 endpoint 的 `chat-completions` 适配器，默认 `deepseek-flash`，启用 thinking 并采用 low 推理强度。
- TTS 通过 Windows PowerShell 调用 System.Speech，生成 16 kHz 单声道 WAV，文本通过临时 UTF-8 文件传递。
- 单提供方请求超时 90 秒，服务端限制识别与回复文本长度。
- 模型替换通过 Protocol 与工厂映射实现。真实流式输出和工具调用仍为预留能力。
- 实现见 [providers.py](../../../voice_platform/providers.py)，官方来源见[运行指南](../../运行指南.md)。
