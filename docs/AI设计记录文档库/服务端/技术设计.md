## 双模式与 S2S 适配

- 本机管理页位于 `/admin`，管理接口检查回环地址、Host 和写入请求的 Origin。接口只返回可编辑项与凭据状态。
- 保存时校验并准备新配置，原子写入本地文件后替换运行快照。已有实时会话和已接收的串联请求继续使用原快照。
- S2S 连接检查只建立模型会话，不提交语音。环境变量优先级沿用启动配置。

- `dialogue.mode=s2s` 为新配置默认值，`cascade` 为 ASR → LLM → TTS 串联模式。旧配置缺少该字段时沿用串联模式。
- 设备通过能力接口查询模式。网页保存新模式后对新会话生效，设备暂停再继续时重新查询。
- S2S 仅构建实时提供方，不初始化独立 ASR、LLM、TTS，也不要求这些模型的密钥。
- `RealtimeSession` 契约包含 open、append、respond 和 close；respond 输出平台音频、文字增量与轮次完成事件。
- 首个适配器为 `qwen-realtime`，默认 `qwen3.8-omni-flash-realtime`，北京地域，音色 Tina。
- 上游地址由业务空间 ID 与地域生成，支持显式 URL。接入其他模型时需检查协议和音频规格，改模型名不代表自动兼容。
- 使用官方嵌套 `session.audio` 配置：输入 16 kHz 单声道 s16le PCM，输出 24 kHz 单声道 PCM。
- Manual 模式：等 session.created，发 session.update，等 session.updated 后传音频；提交后等 input_audio_buffer.committed，再发 response.create。
- 每个设备会话独占上游 WebSocket，同一连接保留音频上下文；响应 ID 与本地轮次关联，断线关闭上游，不自动重放。
- 输出 response.audio.delta 与文字 delta 映射为平台事件；只有 completed 且收到语音才视为成功。
- S2S 默认用 `qwen3-asr-flash-realtime` 接收用户转写，可在管理页关闭。转写按上游音频项 ID 匹配，结束时最多额外等待一秒，缺失时仍保留回复。
- S2S 注册无参数的 `end_conversation` 工具，收到有效调用时发送结束事件并关闭当前会话。工具作用域由连接决定。Findtools 业务工具、全双工打断和会话迁移仍待接入。
- 串联和 S2S 轮次写入本机 SQLite，以模式、设备、会话和轮次标识去重。管理页按游标分页读取。记录保存文字、状态和耗时，不保存音频及凭据。
- S2S 新增 `timings` 字段，旧数据库启动时迁移，旧记录为无分段数据。
- 从收到 `input.commit` 计时，记录首个音频与文字增量、MCP 调用次数和耗时。输入接收时长从 `turn.start` 计时，会话准备耗时只记于首轮。
- 各项存在包含和重叠关系。MCP 时间包含在首包等待及整轮处理中。设备播放时间由设备端另行测量。
- 实现见 [realtime.py](../../../voice_platform/realtime.py)和[realtime_server.py](../../../voice_platform/realtime_server.py)，端间契约见[端间协议与会话](../跨模块设计/端间协议与会话.md)。
- 官方依据：[千问实时模型](https://help.aliyun.com/zh/model-studio/realtime)。本地模拟测试验证协议和流传输，不代表云端账号权限或方言效果已通过。

## 模型能力契约

以下为串联模式的长期能力契约。首版签名为 transcribe(wav)、reply(messages)、synthesize(text)，该路径的流式及工具能力为后续扩展。

| 适配器 | 输入 | 标准输出 | 可选能力 |
| --- | --- | --- | --- |
| STTProvider | 带格式的音频流或完整音频、语言及会话信息 | 转写文字、最终结果标记、错误 | 中间结果、时间戳 |
| LLMProvider | 标准化消息列表、生成选项、可选业务工具描述 | 回复文本、完成状态、可选结构化业务请求、错误 | 流式输出、工具调用 |
| TTSProvider | 回复文本、音色及输出格式偏好 | 音频块或完整音频、实际格式、完成状态、错误 | 流式合成 |

- 提供方声明输入格式、流式支持、取消及其他可选能力。
- 在线适配器封装鉴权和远端协议，本地适配器封装模型加载或本地推理服务。
- 调用方依赖统一契约，供应商专有参数集中在提供方配置中。
- 不支持的能力明确返回，必要时将完整结果包装为单个最终输出。
- 模型切换按会话固定配置快照，避免同一轮处理中途切换。
- 供应商密钥保存在服务端配置，普通音频终端只需平台连接信息。
- 音频校验、增强与提供方格式适配的分工见[音频处理边界](../跨模块设计/端间协议与会话.md#音频处理边界)。带口音普通话和四川话的 STT 实测待凭据，不以 LLM 的文字理解能力替代识别验收。

## 对话与合成

- 会话上下文按设备与会话隔离，语音结束后将最终转写提交对话处理。
- 识别前缀中的唤醒词移除策略需结合设备边界信息，避免简单全局文本替换。
- 当前只处理对话文本。工具调用和 Findtools 业务适配待实现，提示词要求不声称已执行实际业务。
- 首版可先收齐回复再合成，可选流式能力由适配器声明。
- 取消、超时与迟到结果按统一会话标识处理，避免播放上一轮回复。

## 首版实现

- STT 提供 `doubao` 和 `vosk` 两个适配器，后者可在本地识别完整指令。
- LLM 使用可配置 endpoint 的 `chat-completions` 适配器，默认 `deepseek-flash`，启用 thinking 并采用 low 推理强度。
- TTS 通过 Windows PowerShell 调用 System.Speech，生成 16 kHz 单声道 WAV，文本通过临时 UTF-8 文件传递。
- 单提供方请求超时 90 秒，服务端限制识别与回复文本长度。
- 串联模型替换通过 Protocol 与工厂映射实现，该路径的流式输出和工具调用仍为预留能力；S2S 流式输出见前述独立适配。
- 实现见 [providers.py](../../../voice_platform/providers.py)，官方来源见[运行指南](../../运行指南.md)。
