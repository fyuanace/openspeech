## 外部 MCP 工具

| 环节 | 首版机制 |
| --- | --- |
| 管理配置 | 最多 8 台服务器，每台最多 16 个工具，同时最多启用 64 个工具。远程地址用 HTTPS，本机可用 HTTP |
| 工具发现 | openspeech建立 MCP 会话，初始化并调用 `tools/list`。管理页列出可接入的工具，管理员逐个勾选 |
| 模型注册 | 新 S2S 会话并行发现已启用服务器的工具，按服务器 ID 隔离同名工具。说明中带服务器名称 |
| 执行 | 千问发出结构化调用，openspeech校验参数并通过 MCP `tools/call` 执行 |
| 结果 | 结构化数据或文本回传给千问，由千问继续生成回复。连接、校验或执行失败反馈失败 |

- openspeech使用官方 MCP Python SDK。令牌仅发送到保存的 MCP 地址，禁止重定向。网页仅显示令牌配置状态。
- 更换地址会清除工具授权。若已保存令牌，管理员需要清除旧令牌或填写新令牌。
- 旧单服务器配置会出现在新列表中，原地址、令牌和授权保留。管理台首次修改 MCP 配置时保存为多服务器格式。
- 每个会话独立读取工具清单。发现最多等待 5 秒，失败时继续普通对话。
- 每次执行单独建立 MCP 会话，最多等待 12 秒。单轮 MCP 工具调用最多四次，按模型调用标识去重，超时后不自动重试。
- Windows PC 通过 `serve-tools` 启动本机 MCP 服务。工具定义由该服务通过 `tools/list` 返回，执行结果以结构化数据返回。
- 当前支持 JSON 对象参数和文本或结构化结果。串联模式、OAuth 登录和反向连入仍属扩展项。
- 实现见 [mcp_tools.py](../../../voice_platform/mcp_tools.py)。

## 外部业务事件草案

- 接入项目可订阅最终识别文本及回复状态，延续原有文本接入方向。
- 对话模型产生业务请求时，由接入方将请求映射为项目已有业务操作。
- 事件草案包含事件 ID、设备 ID、会话 ID、轮次 ID、类型和载荷。
- 业务请求和执行结果通过独立请求 ID 关联，接入方按 ID 去重。
- 重连补发、结果过期及目标项目选择需在正式契约中明确。
- 端间音频协议集中记录在[端间协议与会话](../跨模块设计/端间协议与会话.md)。

## 验证计划

- 示例客户端分别验证识别文本订阅和业务请求结果关联。
- 模拟重复或迟到消息，检查业务操作不会被重复执行。
- 对接 Findtools 时使用测试实例，命令与亮灯规则由 Findtools 设计确定。
