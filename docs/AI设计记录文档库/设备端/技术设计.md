# 设备端技术设计

- 所属模块为设备端。
- 对应开发者设计为[设备端](../../开发者设计文档库/设备端.md)。
- 返回[技术索引](../index.md)。
- 更新日期为 2026-11-04，以下为拟议技术方案，当前待开发和验证。

## 音频连续性方案

- 采集线程持续写入有界环形缓冲，唤醒检测读取同一音频时间线。
- 每个采样块带单调递增序号或采样位置。唤醒事件保存对应时间位置。
- 触发后发送覆盖唤醒点前后的缓冲音频，并接续实时分片。
- 缓冲回放与实时流交接按序号去重，避免漏帧和重叠提交。
- 建连、提示音、模型准备期间继续保留音频。缓冲超限时明确报错。
- 唤醒词截取优先依据可靠边界信息；边界不可用时保留前缀，避免固定裁剪丢失指令开头。

## 硬件与唤醒适配

- 采集、唤醒和播放各自通过适配层接入 Windows 系统设备或后续硬件。
- 初始规范化格式可使用 16 kHz、单声道、16-bit PCM，最终传输格式通过能力协商确定。
- 原始采样率与播放格式可不同，由相应适配层转换。
- 唤醒适配器输出事件及可选评分，封装引擎所需分帧与状态。
- OpenWakeWord、Porcupine 为此前讨论候选，Windows 与后续硬件的可用性需选型验证。

## 播放与会话

- 回复音频按会话和轮次排队，丢弃已取消轮次的迟到数据。
- 收音与自身播报的串扰需验证，回声处理和播放期间监听策略待确定。
- 状态初稿为等待唤醒、采集指令、等待回复、播放、完成或失败。
- 多轮与打断规则按开发者设计确定后扩展状态。

## 验证计划

- 用可追踪采样序号的样本验证唤醒触发前后没有缺口和重复。
- 覆盖零停顿连说、短指令、慢建连、断流和播放失败。
- 对真实麦克风单独验证音频链路，不以文本注入代替一语即达验收。
