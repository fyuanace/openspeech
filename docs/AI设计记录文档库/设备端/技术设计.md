## 音频连续性方案

- 采集线程持续写入有界环形缓冲，唤醒检测读取同一音频时间线。
- 单一采音队列按顺序交付 20 ms PCM 帧，唤醒时将环形缓冲一次转入本轮录音。
- 触发后保留缓冲音频，接续录音直到静音结束，再发送完整 WAV。
- 触发帧已在缓冲内，只转移一次，后续帧逐帧追加。
- 初始化唤醒模型后才开始采音，录音完成后再建连。采音队列溢出时丢弃本轮并明确提示重新唤醒。
- 唤醒词截取优先依据可靠边界信息；边界不可用时保留前缀，避免固定裁剪丢失指令开头。

## 硬件与唤醒适配

- 采集、唤醒和播放各自通过适配层接入 Windows 系统设备或后续硬件。
- 初始规范化格式可使用 16 kHz、单声道、16-bit PCM，最终传输格式通过能力协商确定。
- 原始采样率与播放格式可不同，由相应适配层转换。
- 唤醒适配器输出事件及可选评分，封装引擎所需分帧与状态。
- 首版使用 Vosk 小型中文模型匹配可配置唤醒词，默认“你好助手”。OpenWakeWord、Porcupine 为后续候选适配。

## 播放与会话

- 当前同步处理一轮，核对响应会话和轮次后播放。远程取消与迟到流式数据处理待实现。
- 当前在模型处理和播报期间关闭采音，播报结束后重新监听。全双工、回声处理与打断为后续能力。
- 状态初稿为等待唤醒、采集指令、等待回复、播放、完成或失败。
- 多轮与打断规则按开发者设计确定后扩展状态。

## 验证计划

- 用可追踪采样序号的样本验证唤醒触发前后没有缺口和重复。
- 覆盖零停顿连说、短指令、慢建连、断流和播放失败。
- 对真实麦克风单独验证音频链路，不以文本注入代替一语即达验收。

## 重要设计变更

- CHG-001，2026-11-04，原缓冲与唤醒方案集中到设备端，增加连续音频交接和回复播放设计。

## 已执行验证

- Windows Huihui 合成“你好助手帮我找十字螺丝刀”，Vosk 在约 1.34 秒触发唤醒。
- 形成一次完整指令，原始 PCM 全部保留，触发前后没有丢失或重复。
- 当前默认 USB 麦克风和耳机的 16 kHz 单声道格式检查通过。
- 测试使用合成样本，真实人声、距离与背景噪声效果仍需现场验收。
