## 首次准备

1. 按 [部署指南](部署指南.md) 运行 `deploy.cmd`，准备环境并启动服务端。
2. 仅准备环境可用 `deploy.cmd -PrepareOnly`；原 `setup.cmd` 入口继续可用。
3. 打开 [管理台](http://127.0.0.1:8765/admin)，按下述步骤配置模型。默认优先 S2S。

## 网页配置

1. 选择 S2S 或串联模式。
2. S2S 选择接入平台。千问 AI 平台自动填写实时地址，百炼填写地域和业务空间 ID，自定义平台填写 WebSocket 地址。
3. 填写模型凭据并保存。已保存的凭据留空保留，网页只显示配置状态。
4. S2S 配置齐全后点「测试 S2S 连接」。验证成功后启动设备端，用“小智小智”唤醒。

- 管理页只接受服务端电脑的本机访问。
- 「运行状态」显示当前模式、运行时长、实时会话、处理中的轮次和日志存储状态，每 5 秒刷新。
- 「对话日志」查看服务端收到的轮次，可加载更早的记录。历史保存在 `data/conversations.sqlite3`，重启后可继续查看。
- 新 S2S 日志按“说话 → 静音判停 → 提交音频 → 等待回复 → 播放回复”展示，汇总“说完到开播”和“完整交互”。设备与服务端均需使用新版。
- 首次唤醒显示估算开口到检测到唤醒的时间；已包含在主流程内，不重复相加。连续追问无需再次唤醒。
- 说话起止按音量估算，包含句中停顿。等待回复包含网络与模型处理，播放时间包含后续语音的生成和传输。
- 阶段耗时、汇总耗时和唤醒状态合并为同一标签区。服务端排查指标继续保存于日志数据，不在页面展示。
- 历史记录和未上报阶段显示缺失；不会补造计时。完整计时在设备播放结束、回报成功后可刷新查看。
- S2S 默认启用用户语音转写。可在「模型与音色」关闭转写，仍保存回复文字和轮次结果。
- 保存后新会话使用新配置。切换模式后，在设备托盘暂停再继续监听。
- 通过环境变量管理的字段保留环境变量优先级。以下是脚本部署可用的变量。

| 服务 | 配置方式 |
| --- | --- |
| 千问 S2S | `DASHSCOPE_API_KEY` 和 `DASHSCOPE_WORKSPACE_ID`，分别对应 `s2s.api_key` 与 `s2s.workspace_id` |
| 豆包新版 | `DOUBAO_API_KEY`，账号需开通 `volc.bigasr.auc_turbo` |
| 豆包旧版 | `DOUBAO_APP_ID` 与 `DOUBAO_ACCESS_TOKEN` |
| DeepSeek | `DEEPSEEK_API_KEY` |
| 平台连接 | 初始化自动生成 token，两端配置使用同一值 |

- 密钥和实际配置只保存在被 Git 忽略的本地文件或环境变量中。
- S2S 默认模型为 `qwen3.8-omni-flash-realtime`，音色为 Tina。使用百炼时，API Key、业务空间和模型权限必须属于对应地域。
- S2S 不需要豆包、DeepSeek 或 Windows TTS 凭据。需要自定义地址时填写 `s2s.url`，地址仍由服务端持有。
- 串联模式使用豆包录音极速识别、DeepSeek `deepseek-flash` thinking 和 Windows TTS。
- 默认唤醒词为“小智小智”，可在设备配置中修改。
- 目标为带地方口音的普通话及四川话；新唤醒词已通过合成样本检查，真实口音及两种模式云端效果尚未验收。
- 串联 TTS 使用 Windows 的 `Microsoft Huihui Desktop` 音色；S2S 直接播放模型生成的语音。

## 切换对话模式

| 模式 | 配置 | 处理路径 |
| --- | --- | --- |
| S2S，默认 | `dialogue.mode = "s2s"` | 音频流 → 千问实时模型 → 语音流 |
| 串联 | `dialogue.mode = "cascade"` | 完整 WAV → ASR/STT → LLM → TTS |

- 在管理页选择模式并保存。设备在继续监听时重新查询服务端模式。
- 也可用下面的命令临时覆盖服务端模式，配置文件保持原值。
- 模式切换建立新会话，不迁移已有上下文。失败不自动降级或重放音频。
- 旧配置没有 `dialogue` 字段时沿用串联模式。升级到 S2S 时按示例补充 `dialogue` 和 `s2s` 两节，保留已有平台 token。

```powershell
.\.venv\Scripts\python.exe -m voice_platform serve --mode s2s
# 切换时先停止上面的服务，再启动另一模式：
.\.venv\Scripts\python.exe -m voice_platform serve --mode cascade
```

## 先验证唤醒

1. 双击 `test-wake.cmd`，等待“本地唤醒测试”。
2. 在 60 秒内连说“小智小智帮我找十字螺丝刀”，说完停顿约两秒。
3. 观察“已唤醒”和“唤醒测试通过”，同时查看录音时长及音量。
4. 确认实际唤醒效果后，再填写云端凭据并启动完整链路。

- 此入口只使用本地麦克风、Vosk 和录音缓冲，无需启动服务端或填写模型凭据。
- 完成一次录音或达到时限后结束，窗口保留结果。
- 音频只在内存中处理，测试不保存录音文件。
- 测试窗口显示本地识别文字，未唤醒时可据此检查模型是否听对唤醒词。
- 命令行可使用 `python -m voice_platform wake-test --seconds 60` 调整测试时长。

## 启动

1. 运行 `start-server.cmd`，默认监听 `127.0.0.1:8765`。
2. 运行 `start-device.cmd`，在 Windows 系统托盘中找到“openspeech”。折叠的图标可点任务栏右侧的“^”查看。
3. 连说“小智小智帮我介绍一下这个平台”，停顿结束后等待语音回复。
4. 在托盘菜单选择“退出”停止设备端。服务端窗口按 Ctrl+C 停止。

### 托盘菜单

| 操作 | 行为 |
| --- | --- |
| 服务端状态 | 显示可连接、待配置或不可达。连接时显示 S2S 或串联模式 |
| 暂停监听 / 继续监听 | 暂停时释放麦克风。继续时重新连接并等待唤醒 |
| 显示桌面悬浮图标 | 显示或隐藏右下角圆形气泡，状态点显示设备状态，点击打开交互过程 |
| 唤醒日志 | 查看带时间的唤醒事件 |
| 交互过程 | 查看连接、采音、处理、播放、可用文字和错误 |

- 日志保留本次运行最近 200 条事件，退出后清空。
- 服务端状态按健康接口刷新，可连接只表示平台可达且配置齐全。
- 串联模式已提交的请求可能要等返回后才显示“已暂停”，回复会被丢弃。
- 更新已有环境可运行 `setup.cmd` 安装托盘依赖。命令行设备入口仍可用 `python -m voice_platform listen` 启动。

- 使用默认系统音频输出设备播放，可通过配置指定输入、输出设备编号。
- S2S 首轮唤醒后，每次播报结束可直接追问，默认等待 20 秒。超时结束对话，下次需重新唤醒。可用 `device.follow_up_seconds` 调整，设为 0 可关闭连续对话。
- 等待追问时说「退出」「请退出」或「结束对话」，音频会交给服务端模型，由内置工具结束本次会话。
- 其他说法也可以表达结束意图，例如「今天聊到这儿吧」。S2S 模型可请求服务端结束本次会话，设备在交互记录里确认退出。
- 处理和播放期间暂停采音。串联模式仍逐轮唤醒。
- S2S 先在本地等待唤醒，唤醒时建立或复用会话。建连期间保留本轮音频，回复边收边播。同一会话内保留上下文。
- 实时会话过期后，下次唤醒会建立新会话。若传输中断，请重说当前指令。
- 连续保留唤醒前 4 秒音频，默认静音 0.8 秒结束，单轮最多 30 秒，参数可调整。
- 背景噪声较大时需要调整 `energy_threshold` 并实测唤醒效果。
- 缺少云端凭据或服务端未启动时，设备仍可测试本地唤醒。唤醒并收完这一句后，交互过程显示服务端提示，设备继续等待下一次唤醒。
- 串联 TTS 失败时保留回复文本；S2S 失败显示错误并关闭连接。

## 测试设备音量工具

1. 在项目根目录运行 `.\.venv\Scripts\python.exe -m voice_platform serve-tools`，启动 Windows MCP 服务。
2. 启动 openspeech 服务端和 Windows 语音前端。后台保持 S2S 模式。
3. 按下方 MCP 接入流程填写 `http://127.0.0.1:18766/mcp`。令牌留空，发现并启用 `set_volume`。
4. 新开一次会话，说「小智小智，把电脑音量调到百分之三十」。检查 Windows 默认播放设备的主音量和助手的语音确认。

Windows MCP 服务仅监听本机地址，适用于 Windows 工具服务与 openspeech 服务端同机运行。调节主音量时保留静音状态。依赖未安装时先按 [部署指南](部署指南.md) 准备环境。

## 接入 MCP 工具

1. 在[服务端管理页](http://127.0.0.1:8765/admin)打开「MCP 服务器」，点击「添加服务器」。
2. 填写名称和 Streamable HTTP 地址。服务要求 Bearer 令牌时单独填写。点击「保存服务器」。
3. 点击「发现工具」，勾选需要开放给助手的工具，再次保存。可在列表中继续添加其他服务器。
4. 新开一次语音会话，直接说出工具对应的任务。

可使用本机地址 `http://127.0.0.1:8000/mcp`。远程服务使用 HTTPS，并填写完整端点路径。可通过「启用服务器」开关暂停某台服务器的工具。语音调用目前使用 S2S 模式。

管理台使用 Vue 3 和 Element Plus。修改前端源码后，在 `admin_frontend` 执行 `npm ci` 和 `npm run build`。运行 openspeech 服务端时直接使用已构建的静态文件。

## 调试命令

在 openspeech 项目根目录执行。

```powershell
.\.venv\Scripts\python.exe -m voice_platform doctor
.\.venv\Scripts\python.exe -m voice_platform devices
.\.venv\Scripts\python.exe -m voice_platform send-wav --file sample.wav
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`send-wav` 接收 16 kHz、单声道、16-bit PCM WAV，自动跟随服务端模式并播放回复；S2S 提取 PCM 分片发送。每次命令创建独立会话。

本机已安装 Vosk 模型和 Windows 中文音色时，可运行合成语音回归检查。覆盖 2 个唤醒样本、6 个非唤醒样本及录音连续性；不代替真实人声验收。

```powershell
$env:VOICE_TEST_WAKE_MODEL = "1"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
Remove-Item Env:VOICE_TEST_WAKE_MODEL
```

## 模型扩展

| 能力 | 已实现适配 | 配置 |
| --- | --- | --- |
| S2S | Qwen Realtime，当前适配嵌套 session.audio 协议 | `s2s.provider`、`model`、`region`、`workspace_id`、`url`、`voice` |
| STT | 豆包在线、Vosk 本地 | `stt.provider` 选择 `doubao` 或 `vosk` |
| LLM | Chat Completions 协议 | `llm.url`、`model`、`options`；可指向兼容的本地服务 |
| TTS | Windows 本地语音合成 | `tts.provider=windows` 与音色名 |
| 唤醒 | Vosk 中文模型识别唤醒词 | `device.wake_model`、`wake_word` |

- 新适配器实现 `providers.py` 的对应 Protocol，并登记到 `build_providers`。
- 新 S2S 适配器实现 `realtime.py` 的 RealtimeSession，并接入 `build_realtime`；供应商事件转为平台流事件。
- 新唤醒引擎实现 `audio.py` 的 WakeDetector 契约，再接入设备创建逻辑。
- 树莓派和 ESP32 的原生设备程序待开发，当前具备 HTTP 与 WebSocket 端间接口。
- 本地模型及不同在线提供方需分别验证实际效果与兼容性。

## 独立项目与 Git

- 项目使用独立 Git 仓库，可放在用户有写权限的目录，`.git/` 保存提交历史。
- Findtools 通过 MCP 使用功能接口，两项目分别维护代码、依赖和提交。
- GitHub 公有仓库为 [fyuanace/openspeech](https://github.com/fyuanace/openspeech)，远程名称为 `origin`。
- 默认分支为 `main`。项目自有内容使用 [PolyForm Noncommercial 1.0.0](../LICENSE)，第三方内容保留原许可。
- 首次准备后可运行 `openspeech --help`；现有 `voice-platform` 命令继续可用。
- 迁移到其他位置后，重新运行 `setup.cmd` 更新 Python 环境和安装入口；保留 `config.local.json`、`data/` 和 `models/`。
