# 运行指南

返回[文档索引](index.md)。代码版本为 0.1.0。

## 首次准备

1. 安装 Python 3.12，在 voice 目录运行 `setup.cmd`。
2. 系统 Python 启动器找不到 3.12 时，运行 `setup.cmd -Python "Python可执行文件路径"`。
3. 脚本建立独立虚拟环境，安装依赖，下载中文 Vosk 模型，并生成 `config.local.json`。
4. 先按下文验证本地唤醒，再配置当前对话模式。默认优先 S2S。

| 服务 | 配置方式 |
| --- | --- |
| 千问 S2S | `DASHSCOPE_API_KEY` 和 `DASHSCOPE_WORKSPACE_ID`，分别对应 `s2s.api_key` 与 `s2s.workspace_id` |
| 豆包新版 | `DOUBAO_API_KEY`，账号需开通 `volc.bigasr.auc_turbo` |
| 豆包旧版 | `DOUBAO_APP_ID` 与 `DOUBAO_ACCESS_TOKEN` |
| DeepSeek | `DEEPSEEK_API_KEY` |
| 平台连接 | 初始化自动生成 token，两端配置使用同一值 |

- 密钥和实际配置只保存在被 Git 忽略的本地文件或环境变量中。
- S2S 默认 `qwen3.8-omni-flash-realtime`，北京 `cn-beijing`，音色 Tina。API Key、业务空间和模型权限必须属于对应地域。
- S2S 不需要豆包、DeepSeek 或 Windows TTS 凭据。需要自定义地址时填写 `s2s.url`，地址仍由服务端持有。
- 串联模式使用豆包录音极速识别、DeepSeek `deepseek-flash` thinking 和 Windows TTS。
- 默认唤醒词为“小美小美”，可在设备配置中修改。
- 目标为带地方口音的普通话及四川话；新唤醒词已通过合成样本检查，真实口音及两种模式云端效果尚未验收。
- 串联 TTS 使用 Windows 的 `Microsoft Huihui Desktop` 音色；S2S 直接播放模型生成的语音。

## 切换对话模式

| 模式 | 配置 | 处理路径 |
| --- | --- | --- |
| S2S，默认 | `dialogue.mode = "s2s"` | 音频流 → 千问实时模型 → 语音流 |
| 串联 | `dialogue.mode = "cascade"` | 完整 WAV → ASR/STT → LLM → TTS |

- 修改 `config.local.json` 后重启两端。设备自动查询服务端模式，不需要配置供应商协议。
- 也可用下面的命令临时覆盖服务端模式，配置文件保持原值。
- 模式切换建立新会话，不迁移已有上下文。失败不自动降级或重放音频。
- 旧配置没有 `dialogue` 字段时沿用串联模式。升级到 S2S 时按示例补充 `dialogue` 和 `s2s` 两节，保留已有平台 token。

```powershell
.\.venv\Scripts\python.exe -m voice_platform serve --mode s2s
# 切换时先停止上面的服务，再启动另一模式：
.\.venv\Scripts\python.exe -m voice_platform serve --mode cascade
```

## 先验证唤醒

1. 双击 `test-wake.cmd`，等待“本地唤醒测试”。
2. 在 60 秒内连说“小美小美帮我找十字螺丝刀”，说完停顿约两秒。
3. 观察“已唤醒”和“唤醒测试通过”，同时查看录音时长及音量。
4. 确认实际唤醒效果后，再填写云端凭据并启动完整链路。

- 此入口只使用本地麦克风、Vosk 和录音缓冲，无需启动服务端或填写模型凭据。
- 完成一次录音或达到时限后结束，窗口保留结果。
- 音频只在内存中处理，测试不保存录音文件。
- 测试窗口显示本地识别文字，未唤醒时可据此检查模型是否听对唤醒词。
- 命令行可使用 `python -m voice_platform wake-test --seconds 60` 调整测试时长。

## 启动

1. 运行 `start-server.cmd`，默认监听 `127.0.0.1:8765`。
2. 运行 `start-device.cmd`，在 Windows 系统托盘中找到“小美语音”。折叠的图标可点任务栏右侧的“^”查看。
3. 连说“小美小美帮我介绍一下这个平台”，停顿结束后等待语音回复。
4. 在托盘菜单选择“退出”停止设备端。服务端窗口按 Ctrl+C 停止。

### 托盘菜单

| 操作 | 行为 |
| --- | --- |
| 服务端状态 | 显示可连接、待配置或不可达。连接时显示 S2S 或串联模式 |
| 暂停监听 / 继续监听 | 暂停时释放麦克风。继续时重新连接并等待唤醒 |
| 显示桌面悬浮图标 | 显示或隐藏右下角圆形气泡，状态点显示设备状态，点击打开交互过程 |
| 唤醒日志 | 查看带时间的唤醒事件 |
| 交互过程 | 查看连接、采音、处理、播放、可用文字和错误 |

- 日志保留本次运行最近 200 条事件，退出后清空。
- 服务端状态按健康接口刷新，可连接只表示平台可达且配置齐全。
- 串联模式已提交的请求可能要等返回后才显示“已暂停”，回复会被丢弃。
- 更新已有环境可运行 `setup.cmd` 安装托盘依赖。命令行设备入口仍可用 `python -m voice_platform listen` 启动。

- 使用默认系统音频输出设备播放，可通过配置指定输入、输出设备编号。
- 每次指令重新唤醒。处理和播放期间暂停采音，当前采用半双工交互。
- S2S 在就绪后开始本地监听，唤醒后立即传音频，回复边收边播；同一连接保留上下文，不代表已经实现边说边听或打断。
- S2S 空闲三分钟、会话三十分钟或 128 轮后关闭；断线或超时需重启设备端建立新会话。
- 连续保留唤醒前 4 秒音频，静音 1.2 秒结束，单轮最多 30 秒，参数可调整。
- 背景噪声较大时需要调整 `energy_threshold` 并实测唤醒效果。
- 缺少云端凭据或服务端未启动时，设备仍可测试本地唤醒。唤醒并收完这一句后，交互过程显示服务端提示，设备继续等待下一次唤醒。
- 串联 TTS 失败时保留回复文本；S2S 失败显示错误并关闭连接。

## 调试命令

在 voice 目录执行。

```powershell
.\.venv\Scripts\python.exe -m voice_platform doctor
.\.venv\Scripts\python.exe -m voice_platform devices
.\.venv\Scripts\python.exe -m voice_platform send-wav --file sample.wav
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`send-wav` 接收 16 kHz、单声道、16-bit PCM WAV，自动跟随服务端模式并播放回复；S2S 提取 PCM 分片发送。每次命令创建独立会话。

本机已安装 Vosk 模型和 Windows 中文音色时，可运行合成语音回归检查。覆盖 2 个唤醒样本、6 个非唤醒样本及录音连续性；不代替真实人声验收。

```powershell
$env:VOICE_TEST_WAKE_MODEL = "1"
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
Remove-Item Env:VOICE_TEST_WAKE_MODEL
```

## 模型扩展

| 能力 | 已实现适配 | 配置 |
| --- | --- | --- |
| S2S | Qwen Realtime，当前适配嵌套 session.audio 协议 | `s2s.provider`、`model`、`region`、`workspace_id`、`url`、`voice` |
| STT | 豆包在线、Vosk 本地 | `stt.provider` 选择 `doubao` 或 `vosk` |
| LLM | Chat Completions 协议 | `llm.url`、`model`、`options`；可指向兼容的本地服务 |
| TTS | Windows 本地语音合成 | `tts.provider=windows` 与音色名 |
| 唤醒 | Vosk 中文模型识别唤醒词 | `device.wake_model`、`wake_word` |

- 新适配器实现 `providers.py` 的对应 Protocol，并登记到 `build_providers`。
- 新 S2S 适配器实现 `realtime.py` 的 RealtimeSession，并接入 `build_realtime`；供应商事件转为平台流事件。
- 新唤醒引擎实现 `audio.py` 的 WakeDetector 契约，再接入设备创建逻辑。
- 树莓派和 ESP32 的原生设备程序待开发，当前具备 HTTP 与 WebSocket 端间接口。
- 本地模型及不同在线提供方需分别验证实际效果与兼容性。

## Git 子模块

- voice 拥有独立提交历史，Findtools 记录其提交指针。
- 当前使用本机 bare 仓库作为临时 origin，位置由 `git remote -v` 查询。
- 跨电脑克隆前需配置正式远程，并同步父仓库 `.gitmodules` 中的 URL。
- 提交 voice 后，另在 Findtools 提交子模块指针。
