## 职责与功能

| 能力 | 输入 | 输出 | 首版方向 |
| --- | --- | --- | --- |
| S2S 实时语音对话 | 音频流 | 回复语音流及可选文字 | 通义千问，当前优先 |
| STT 语音转文字 | 指令音频 | 识别文字 | 在线豆包 |
| LLM 对话处理 | 用户文字与会话上下文 | 回复文字及可选业务请求 | 在线 DeepSeek |
| TTS 文字转语音 | 回复文字及合成选项 | 可播放音频 | 首版实现采用 Windows Huihui 本地语音合成 |

- S2S 与 ASR → LLM → TTS 两种模式可切换，默认优先 S2S。
- S2S 提供方独立替换，串联模式的三类能力分别可替换，接口覆盖本地模型及在线服务。
- 模式按会话固定，切换建立新会话，不把两种引擎的上下文自动混用。
- S2S 失败明确报错，不自动改用串联服务，避免重复处理和隐式费用。
- 首版可只接入选定提供方，扩展其他模型时沿用共同能力接口。
- 识别、对话与语音合成的结果必须归属正确设备及会话。
- 业务请求通过通用接入交给业务项目，货架等实际动作由该项目执行。

## 功能行为与接口要求

- 接收设备端音频，按当前模式完成语音问答，返回回复。
- 允许向接入项目提供识别文本，兼容已有查货接入方向。
- 模型自身的格式差异由服务端处理，对设备端提供一致结果。
- 模型不可用、超时或音频不受支持时返回明确错误及失败阶段。
- S2S 和 STT 的目标输入包含带地方口音的普通话和四川话，均需使用目标用户录音验证，尚未验收。
- 设备端唤醒通过与服务端内容识别通过分别验收，不能互相替代。
- S2S 服务端通过 MCP 发现已配置端点提供的工具，将获准工具交给模型。音量操作作用于运行该 MCP 服务的电脑。
- 服务端将设备实际执行结果反馈给模型，再生成语音回复。失败或超时应如实告知。

## 验收与待定

- 独立替换三类适配器，验证设备端和业务项目沿用原接口。
- 千问 S2S 的真实语音闭环已验证。豆包、DeepSeek 与 Windows TTS 的完整串联链路单独验收。
- 在线与本地适配接口均需验证，尚未接入的真实模型单独列明。
- S2S 已实现流式传输，串联流式及业务工具能力待扩展；具体选型与上下文范围见技术记录。

## 网页管理

- 管理页引导选择模式、接入平台、模型与凭据，并显示配置是否齐全。
- 配置保存后对新会话生效。S2S 可单独验证模型连接。
- 首版管理页限定服务端电脑本机访问。
- 管理页提供运行状态和历史对话。日志按轮次保存用户文字、回复及处理结果，重启后保留。
- 管理页提供独立的 MCP 服务器入口，每台服务器单独配置和管理工具。
