## 职责与功能

- 连接音频输入与输出设备，完成采音、唤醒、指令提交及回复播放。
- 首版使用 Windows 10 系统麦克风和系统音频输出设备。
- 后续适配 PC、树莓派、ESP32，各终端使用共同服务接口。
- 启动时查询服务端模式。S2S 模式传音频流、边收边播；串联模式提交完整语句并播放完整回复。
- 两种模式均复用本地唤醒与连续缓冲，设备端不接触供应商协议和云端密钥。
- 终端唤醒引擎可按硬件选择，首版实现采用可配置的 Vosk 中文唤醒，默认“小美小美”，现场效果待验。

## 一语即达

- 唤醒检测期间持续保留音频，唤醒词后的内容可直接连说。
- 唤醒检测延迟不能造成指令开头被丢弃。
- 提示音和网络连接准备不能成为开始说内容的前置步骤。
- 每次指令与对应回复明确关联，取消或失败后显示可理解状态。

## 目标语言与现场效果

- 用户指定唤醒词为“小美小美”。
- 覆盖带地方口音的普通话和四川话发音，当前属于验收目标，尚未完成效果验收。
- 分别检查完整唤醒词、单独“小美”、近音词及日常交谈，避免只优化命中而增加误唤醒。
- 检查不同说话人、距离、音量和背景噪声；同时验证唤醒后连说内容完整。
- 音频处理方案及当前实现状态见[端间协议与会话](../AI设计记录文档库/跨模块设计/端间协议与会话.md#音频处理边界)。

## 接口要求

| 方向 | 交付内容 |
| --- | --- |
| 发往服务端 | 设备身份、会话关联、音频及音频结束或取消信号 |
| 接收服务端 | 识别状态、回复文本、回复音频和错误 |
| 本地音频接口 | 可选择的输入输出设备及其可用状态 |

## 验收与待定

- 连说唤醒词和短指令，检查内容开头完整且没有重复提交。
- 检查麦克风断开、服务断连、播放失败和空指令。
- 结束条件、等待时长、播放时打断及多轮规则待确定。
- 各硬件独立验收，当前阶段完成 Windows 10 路径。

## 重要设计变更

- CHG-001，2026-11-04，将原音频与会话和唤醒能力归入设备端，统一承担一语即达，以支持不同采音硬件。
- CHG-002，2026-11-04，增加独立本地唤醒验证，以便在云端接入前判断设备端是否正常。
- CHG-003，2026-11-04，唤醒词改为“小美小美”，增加地方口音普通话与四川话的独立验收要求。
- CHG-004，2026-11-04，设备端自动跟随服务端选择 S2S 或串联路径，S2S 增加音频流传输和流式播放。

## Windows 托盘

- 设备端启动后显示托盘图标，标记等待唤醒、已唤醒、处理、播放、暂停和失败状态。
- 提供暂停、继续、悬浮状态、唤醒日志、交互过程和退出。
- 暂停期间释放麦克风，继续后恢复唤醒等待。交互过程展示当前模式能提供的文字。
- 本地唤醒可在缺少云端凭据或服务端不可达时运行。唤醒并收完本轮语音后提示服务端状态，然后恢复监听。
- CHG-005，增加本地托盘与监听控制，支持后台运行和现场排查。

## 独立唤醒验证入口

- 先验证本地麦克风、唤醒和连续录音，再连接在线 API 验证完整链路。
- 使用 `test-wake.cmd`，一次录音完成或 60 秒到期后显示结果。
- 详细步骤见[运行指南](../运行指南.md)。
